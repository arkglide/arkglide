## 使用与验收

- 模型从「项目资源」拖入视口。GLB 为自包含资源；glTF 的 bin/贴图需要一起挂载，导入时会内嵌到存储文档。
- 双击代码 Tab 重命名脚本，`main.js` 保留；文件删除会解除绑定，撤销可恢复。
- 场景树 Ctrl/Cmd 点击切换选中，Shift 范围选择；视口 Ctrl/Cmd/Shift 点击加选或减选。Delete 删除全部选中节点。
- 多选 Gizmo 以选中根节点的中心为轴；选中的子节点随父节点变换一次。Inspector 按轴批量输入仍是各节点的局部属性修改。
- Global/Local 控制 Gizmo 坐标轴。F 聚焦世界包围盒；右键按住配合 WASD/QE 飞行，松开或窗口失焦退出。
- 「运行相机」决定播放视角。编辑相机独立于运行相机；场景旧数据未指定运行相机时选择首个可见相机。
- IndexedDB 兼容旧版只有一个表的数据库。项目模型采用项目 ID 隔离，保存元数据与二进制使用同一事务。
- 新建、打开、导入项目清空历史，损坏的 ZIP/场景层级在替换当前项目之前报错。
- 实体销毁会清理后代句柄；模型加载在停止、替换或卸载后完成时会释放过期容器。

## F10 的具体范围

WASM 接管 ArkGlide 脚本 API 的数学计算：`math.vec3`、`math.mat4`、`math.quat`、实体的 `translate/rotate` 与 `getWorldMatrix/getWorldPosition`。返回普通数值对象；内部 Embind 对象由适配层释放。Babylon 的渲染器内部运算和渲染节点仍归 Babylon；F12 已接入独立 C++ 逻辑场景、实体注册和生命周期时钟，边界见 [内核与 UI 设计](runtime-core-and-ui.md)。

`npm run benchmark:math` 与菜单「数学性能基准」比较同一 API 边界：预热、5 次采样中位数，计入参数检查、跨 WASM 调用、分配、结果复制和释放。当前小粒度调用可能明显慢于 JS；没有声称 WASM 必然更快。批量内存接口与减少跨边界调用是后续优化方向。

## 仍存在的边界

- 用户脚本采用 JavaScript；支持项目内相对路径 import/export，不增加 TS 编译。循环依赖、顶层 await、变量路径动态导入、远程/npm 模块暂不支持，详见 [模块文档](javascript-modules.md)。
- 材质与贴图支持项目内编辑/绑定/替换；没有资源目录写回、图像绘制或着色器图。
- 预制体支持编辑器嵌套关联与运行时动态生成，不含模板继承/变体、对象池和独立预制体文件格式。
- Draco/KTX 等压缩资源依赖额外解码器；本轮验收使用标准 GLB/glTF，不宣称已提供所有压缩格式的离线解码。
- F11 已实现本任务单的模型形状、常用关节和原生胶囊角色控制器；软体/布料、车辆等更复杂物理不在本轮范围。
- 编辑器 bundle 仍较大，Node 默认内存不够时可设置 `NODE_OPTIONS=--max-old-space-size=6144`。

## 代表游戏：折径（暂定名 Foldline）

状态：规划，尚未实现以下关卡和游戏文件。现有 `portal-lab` 继续作为穿越与渲染验收场景，`composition-lab` 继续作为机关组合验收场景；代表游戏独立组织内容。相关能力以 [视角与传送门 API](view-and-portals-api.md)、[玩法基础 API](gameplay-foundations-api.md) 的实际边界为准。

### 定位与体验

首版为桌面浏览器、键鼠操作的原创第一人称空间解谜短篇，目标首次游玩约 20～30 分钟，包含六个房间和一个结尾。玩家身处停机的空间中继站，通过配对传送门恢复运输与供能线路，最终抵达中枢。名称、场景、图形标识和声音按本作设计。

核心循环：观察出口与线路 → 放置配对门或搬运物体 → 改变空间路径 → 激活机关 → 抵达下一处安全检查点。每关引入一种主要概念，并复用之前学到的操作；以可观察的因果关系和空间判断形成谜题。玩家能够自由放门，辅助标识说明可放置表面和机关关联。

首版集中完成单人流程、稳定手感、存档重试和整体视听。合作联网、凝胶流体、炮塔战斗、任意重力、长期跨门关节以及长篇演出安排在后续版本评估，不作为本次通关条件。

### 六关设计

| 关卡 | 首次游玩目标 | 主要问题与完成方式 | 对应引擎能力 |
| --- | --- | --- | --- |
| 01 越界 | 2～3 分钟 | 看见隔断另一侧的出口，辨认可放门面，放置两扇门并穿越；两侧均有安全站立区 | 第一人称相机、角色、表面规则、门与视图 |
| 02 借物 | 3～4 分钟 | 箱子位于隔断另一侧；通过所见的入口抓回箱子、放上压板，观察线路点亮并打开出口 | 跨门抓取、刚体、触发器、信号与运动门 |
| 03 落差 | 3～4 分钟 | 利用落差进入地面门，经侧向出口抵达高台；用宽落地区和空间标识引导，不要求窄时间窗口 | 动量转换、角色回正、固定步、坠落重试 |
| 04 折光 | 4～5 分钟 | 通过传送门重新布置光路，操作反射台使接收器供能；灯线明确对应出口状态 | 穿门射线、反射、光束表现、接收信号 |
| 05 铺路 | 4～5 分钟 | 用箱子保持投射器供能，将光桥经门投向缺口，建立到出口的连续步行路径 | 有限体积投射、生成碰撞、压板与资源清理 |
| 06 回流 | 5～7 分钟 | 先在安全区域认识牵引场，再借门将箱子运到压板，维持光桥并抵达中枢完成重启 | 分段力场、刚体/角色、信号组合、结尾与进度 |

第三关的落差、出口朝向和落地区间用真实角色模拟确定。最后一关以牵引运输、供能和通路三者组合收束；激光已在第四关独立展示。具体尺寸和求解路线在灰盒通关后冻结。

### 手感、界面与视听

- WASD 移动，空格跳跃，左右键分别放门，E 抓取/释放或操作所指机关，R 回到检查点，Esc 暂停并释放鼠标。点击重新锁定鼠标的当次输入不得顺带开火或触发机关。按键通过动作映射定义。
- 持物保留真实跨门路径；门关闭、物体失效或距离超限时清晰释放。箱子离开可恢复区域会回到本关补给位，出口前始终提供重试路径。
- 页面加载时显示现有启动终端日志，完成后直接进入游戏；首次用简短提示请求点击锁定鼠标。暂停菜单提供继续、重试、重新开始与设置；开发日志默认隐藏，可由开发者启用。
- 准心由现有 UI 图形和共享样式构成。放置失败、可交互对象与持物状态用形状、图标和颜色共同表达。操作说明按首次遇见、瞄准或暂停时显示；设置解释使用 tooltip，常驻 HUD 只保留必要状态。
- 模块化中继站环境采用清楚的面板、金属结构、供能灯线和少量植被/维护痕迹。可放门面与装饰面具有稳定视觉区别；出口和设备之间有可追踪的线路，不靠满屏文字解释规则。
- 第一人称投射器采用原创简洁模型，配合放门和持物动作。开门、转动反射台和补给箱子均通过场景设备操作；机关的灯光、运动与声音反映实际状态。
- 声音覆盖放门成功/失败、穿越、抓取、落地、压板、机关供能和环境底噪。首个完整版本先确定两关的材质、灯光、音效与 UI，再扩展剩余房间。

### 游戏内容与引擎边界

玩家操作、设备规则、反射台转角、箱子补给、关卡顺序、故事、提示和进度均放在示例游戏脚本与配置中。引擎继续提供通用角色、抓取、表面、投射、力场、触发器、信号、运动、关卡和存档服务。`src/engine` 与 `cpp` 不引用本作名称、关卡 ID 或机关胜利条件。

放门碰撞面使用独立平板或已支持的静态平面区域，装饰模型单独组织。灰盒只采用当前已验证的物理形状与移动方式。开发中若发现可复现的引擎缺陷，先给通用接口补回归，再修示例；性能优化以本作实际 CPU/GPU 分析为依据，继续迁移 C++ 不阻塞首关制作。

### 关卡、重试与资源

引导脚本和玩家跨关存在，每个房间作为独立预制体交给 `levels` 加载，并通过关卡局部 ID 查找设备。切换前释放持物和输入，加载期间禁用交互；新房间报告就绪后再开启操作、进入安全出生位并保存检查点。下一关资源按现有接口预取；旧关卡的订阅、投射网格、碰撞体、力场、音频和渲染对象随作用域释放。

存档使用引擎检查点及游戏 provider：保存版本、当前关卡、已完成进度和需要持久化的机关语义，物理状态交给已有快照机制。光桥几何、牵引场、接收器与压板的派生状态根据恢复后的场景重新计算。运行时随机实体 ID、WASM 视图、渲染纹理和完整网格不写入游戏存档。

失败恢复作为首个版本的功能验收：箱子掉落或卡住、玩家坠落、门在持物时换位、重复触发出口、连续按重试、关卡资源/脚本加载失败、存储不可用、旧版存档不兼容，都应有明确的恢复路径。存档失败允许继续当前游戏并提示重试；加载失败保留重试入口，首阶段实测 `levels` 与 provider 的异常恢复边界，必要时补通用能力。检查点设在安全站立位置，恢复时不保留未完成的拾取操作。

### 性能与验证

参考目标为桌面浏览器 1080p、60 FPS；参考硬件和实际预算在 A 阶段记录后确定。分别采集总帧耗时、CPU/GPU、物理固定步、离屏视图数量/像素和内存，记录中位数与 P95。已有动画 CPU 基准不能替代本作整帧测量。

画质配置保留清晰的首层传送门视图，先限制递归层数、深层分辨率、可见视图和阴影预算；各档参数由实测确定并写入示例配置。每关只加载当前内容及必要预取资源，复用模块化几何与材质，避免不必要的动态刚体、灯光和持续投射重建。

自动回归包括实际放门/穿越/拾取输入、机关因果链、落差通路、光路与投射碰撞、力场、存档继续、异常重试、跨关卸载和多轮启停，以及根目录/子目录独立部署。专门的物理夹具可设置受控位姿，但与完整输入通关测试分开标记。暂停、失焦、指针重新锁定、相机靠近门面、半穿越持物等情况保留图像或视频证据。

人工试玩检查初次理解、瞄准与移动手感、画面清晰度、晕动、提示强度、解法与软锁，并记录实际通关时间。示例验收以完整可玩流程为准；普通内容修改先跑相关回归，只有改动 C++ 才重编 WASM，按需运行前端生产构建。
