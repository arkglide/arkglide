# KTX2 压缩贴图

在「内容 → 贴图」导入或替换 `.ktx2`，再分配到 PBR 材质贴图槽。资源卡显示尺寸、色彩空间和 mip 数；浏览器图片控件不会尝试把 KTX2 当作普通图片预览。导入 [ktx2-lab.arkglide](../examples/ktx2-lab.arkglide) 可查看 UASTC 清漆、ETC1S 色块、细节法线和透明裁切。

支持 2D、单层、单面的 ETC1S/BasisLZ、UASTC 4×4（可含 Zstd）和 RGBA8 KTX2。需要单个 mip 或完整 mip 链；最多 64 MiB 文件、8192 像素单边且不超过 16 MP，并服从当前设备纹理尺寸上限。首版不含立方体、数组、HDR KTX2 或图片编码器；环境光照继续用 `.env`/`.hdr`，HTML UI 图片继续用 PNG/JPEG/WebP。

导入时先校验容器、DFD/KVD、范围、层级和支持格式，再在独立工作线程中调用实际 WASM 解码器验证全部 mip。验证失败、超时、替换竞争和切换项目均不会提交过期结果。工作线程在完成或失败后终止。底层存储 API 同步校验容器，运行时还会按真实文件头检查贴图用途和设备尺寸。

颜色图（albedo、自发光、sheen）尊重文件的线性/sRGB 声明；法线、清漆法线、粗糙度/金属度、AO、光照图、细节等数据图必须采用线性编码。仅接受 BT.709/sRGB 原色和非预乘数据。支持 `rd`、`ru`、`ld`、`lu` 方向；通道重排请在编码时应用，容器中只接受恒等 `rgba` swizzle。

解码器按设备选择 ASTC、BC7、ETC 等 GPU 格式，缺少支持时回退 RGBA。为避免 PVRTC 等设备格式的尺寸限制，非二次幂图片使用 RGBA 回退。保留文件的 mip、alpha 和色彩空间；方向校正在作者的 UV 变换之后应用。法线和细节图单独修正采样坐标，保持原 UV 导数定义的切线方向。此路径也补齐 Babylon 9.28 细节图单独使用时缺失的 UV 属性与自带切线传递，PNG 细节图同样受益。

解码器固定为 Babylon 9.28，JS、WASM、验证线程和许可证随工程及静态包交付。普通编辑视口使用本地文件 URL。游戏运行器保留原有 opaque-origin 沙箱；含 KTX2 的项目按需通过经典脚本加载 `lib/ktx2/decoder-resources.js`，再向原生解码工作线程提供本地数据 URL，避免静态服务器必须配置 CORS。该伴随文件约 894 KiB，内容由同目录的原始解码器和 WASM 自动生成；不含 KTX2 的项目不加载它。没有外部解码 CDN 请求，子目录部署已覆盖。

`npm run dev`、构建和导出的运行时同步直接使用仓库中的离线解码文件，不在启动时重新打包依赖。更新解码器版本时，安装开发依赖后执行 `npm run sync:ktx2`，并一起提交生成的 JS、WASM、伴随数据和许可证；重建使用包的公开入口，不依赖 `legacy/legacy.js` 内部路径。自有验证线程仍由 `sync:runtime` 每次同步。

保存、撤销、复制/粘贴、预制体、分块资源和独立导出保留源字节及容器元数据。局部探针/平面反射材质变体共享源贴图，并保留法线采样修正。停止或清空场景释放自有 GPU 贴图、材质和引用；解码资源随 iframe 生命周期缓存。

资源预算分开报告：

- 文件字节数：压缩资产本身的大小。
- 源尺寸/mip 估算：每个资产的一份 RGBA8 存储，KTX2 使用文件实际 mip 数。
- 已加载 KTX2 副本：按当前 GPU 格式及块尺寸估算；同一图片用于多个材质/槽位可能存在多份自有贴图。尚未就绪或无法识别的格式返回未知。

这些数值不含驱动开销、渲染目标或其他未统计资源，不能当作显存实测值。64×64、7 级 mip 的测试图，RGBA8 为 21,844 字节，ASTC/BC7 为 5,488 字节，无 alpha ETC2 为 2,744 字节；比例随图像、设备格式和尺寸变化。当前自动化采用 SwiftShader，目标机帧率仍需实测。

```sh
npm run example:ktx2
npm run test:ktx2:browser
```
