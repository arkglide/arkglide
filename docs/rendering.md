# 画面与光照

在「菜单 → 项目设置 → 画面与光照」配置阴影、环境光照、色调映射和 AO。旧项目不自动开启新增效果。编辑器、播放预览与独立游戏共用实现。

大气雾、程序天空、景深、GPU 粒子、SSR/平面反射与高级 PBR 层的配置和边界见 [大气、特效与高级材质](advanced-rendering.md)。

光照图生成与方向光 CSM 见 [静态光照制作](lighting-workflow.md)，几何共享/LOD 见 [场景资源优化](scene-scale.md)，设备测量见 [场景性能基准](scene-performance.md)。

## 灯光与环境

开启实时软阴影后，方向光和点光源按场景顺序使用阴影灯数量预算。网格/模型和灯光属性中的「投射阴影」，以及网格的「接收阴影」控制参与对象。方向光的柔和/接触渐变分别使用 PCF/PCSS；点光源和 WebGL1 回退 Poisson。阴影距离控制灯光深度范围，不能替代场景大小和灯光布局设计。

导入预过滤 Babylon `.env` 或 Radiance `.hdr` 环境贴图后可配置环境亮度、旋转和天空盒。HDR 在加载时转换为 128 像素立方体并预过滤；发布建议事先制成 `.env`，避免启动时转换。支持标准 `-Y +X` Radiance RGBE。资源保存在项目内，独立包自动预加载；替换和停止会清理纹理与对象 URL。

## 烘焙光照与环境遮蔽

材质编辑器新增 AO 贴图、AO 强度、烘焙光照贴图、强度和 UV 通道。

- Lightmap 使用**线性数值**，UV2 为默认；在 Blender 等工具中烘焙并导出带第二套 UV 的 GLB，再导入 Lightmap。引擎不自动烘焙、不生成 UV2、不自动打包光照图集。多物体图集需要相应 UV 已位于正确区域。
- 无 UV2 会在控制台提示；只有确实使用第一套 UV 制作的贴图才应选择 UV1。Lightmap 不继承基础色贴图的平铺比例。
- AO 使用线性灰度，主要压暗环境/间接光，不会无条件压暗直射光。场景设置中的 SSAO 需要 WebGL2/MRT；不可用时保留材质 AO，跳过屏幕效果。
- 灯光烘焙中的直射和运行时直射应合理分工，避免把同一盏灯重复叠加。

## 局部反射探针

先导入房间的预过滤 `.env`，再在项目设置中添加探针。中心和范围使用世界坐标，范围是盒子的完整宽/高/深。探针对引擎自有 PBR 材质生效，包括模型部件上分配的自有材质；导入模型原始材质保持原样。

物体世界包围盒中心进入范围时使用局部立方体投影。重叠范围优先级高者优先，相同优先级选择体积小者，再按 ID 排序。离开范围恢复全局环境。共享材质按探针生成轻量变体并共享贴图，防止不同房间相互串用反射。亮度乘在全局环境亮度之上；边界为离散切换，不进行探针混合。最多 32 个探针；本轮使用预烘焙环境，不逐帧捕获动态立方体。

所有引用贯通撤销、项目保存、恢复和独立包；仍在使用的环境、AO 或 Lightmap 无法直接删除。

## 自发光、泛光与调色

材质自发光贴图使用 sRGB，乘以自发光颜色和强度。首次分配自发光贴图时，编辑器把原本的黑色因子改为白色；随后可以继续调整颜色。它不会自动照亮周围几何，周围光照应使用实际灯光或烘焙。

项目设置提供 Bloom 阈值、强度、范围和分辨率比例，以及饱和度、染色色相和染色强度。先确定曝光和色调映射，再调整灯光/自发光强度，最后控制泛光。阈值作用于亮度而非单个 RGB 通道，纯色灯线可能需要更高自发光强度或较低阈值。

启用后处理时，主场景和递归门内图像均保留线性颜色，由主相机统一进行调色和输出转换；设备支持时离屏目标使用浮点 HDR，受限设备回退线性 8 位（高亮范围受限）。不会在每层传送门重复曝光。SSAO 仅作用于主相机，门内不会额外执行 SSAO。门内粒子默认关闭，高画质档位或显式开关可以开启。

## 画质档位与多视图预算

| 项目 | 低 | 中 | 高 |
| --- | --- | --- | --- |
| 主视图分辨率比例 | 0.75 | 1 | 1 |
| 阴影分辨率 / 灯数 | 512 / 1 | 1024 / 2 | 2048 / 4 |
| 阴影过滤 | PCF | PCF | PCSS |
| SSAO | 关闭 | 半分辨率、8 采样 | 全分辨率、16 采样 |
| Bloom | 关闭 | 0.25 比例 | 0.5 比例 |
| 抗锯齿 | FXAA | FXAA | 4× MSAA（不可用时 FXAA） |
| 门递归层数 / 视图上限 | 1 / 4 | 2 / 8 | 2 / 16 |
| 门内分辨率比例 | 0.5 | 0.75 | 1 |
| 离屏像素上限 | 1,048,576 | 3,145,728 | 8,388,608 |
| SSR | 关闭 | 关闭 | 128 步，全分辨率 |
| 平面反射数 / 捕获像素预算 | 关闭 | 1 / 524,288 | 4 / 4,194,304 |
| 景深质量（保留启用状态） | 低 | 中 | 高 |

档位保留环境资源、曝光、调色、自发光和探针定义，只调整效果预算。手动修改参数会标记为自定义。MSAA、浮点纹理和 SSAO 均按设备能力回退；这些档位不是目标设备的帧率保证。

可在脚本中切换本次会话的画质，项目文件保持原设置：

```js
rendering.setQuality('medium');
const settings = rendering.getSettings(); // 独立副本
const stats = rendering.getStats();
```

模块脚本也可使用 `context.rendering`。脚本销毁后其句柄失效，不暴露 Babylon 对象。

传送门先做背面和齐次视锥裁剪，按投影包围矩形面积排序，再分配整个递归树的视图数与总像素预算；根视图先保留预算，子视图使用剩余预算。预算不足时降低目标分辨率，低于最小尺寸则使用门的备用颜色。看不见的门不创建视图，闲置目标立即释放。面积筛选不是场景深度遮挡查询；椭圆门用保守矩形估计。

像素数按每个实际离屏目标的 `width × height` 累计，不乘 MSAA 样本数。分辨率比例、递归比例、最大视图数和总像素数可分别设置。`portals.setQuality()` 的显式字段优先于场景档位，适合游戏自行管理局部需求。

## 诊断与 WASM

运行诊断显示画质、渲染比例、绘制调用、主场景三角形、离屏视图/像素、预算及原生/JS 预算批次。在画面设置中开启 GPU 采样后，支持计时扩展的设备显示有效 GPU 毫秒值；扩展不可用、未开启或尚未返回有效查询时显示未采样，不以 CPU 时间代替。CPU 渲染提交时间包含同步准备和驱动提交，首次编译可能有明显峰值。

`cpp/render/batch.cpp` 新增连续输入/输出批次，执行门的四角投影、六面齐次裁剪、面积排序和像素分配。运行时复用输入缓冲，使用已有 C++/WASM 模块，不额外下载另一份模块。默认 8 个候选起使用 WASM；较小批次或禁用原生渲染计算时使用同语义 JS。可用 `settings.renderCompute.viewsMinPortals` 调整阈值。内存增长后重建视图，返回的数据不引用可失效的 WASM 内存。

`npm run benchmark:views` 比较包含参数校验、输入复制和独立输出对象的 CPU 耗时。每条路径先预热 1,000 次，再取 5 组、每组 100 次的中位值。本次容器 Node 24 基准中，8 个候选约为 JS 0.022 ms / WASM 0.0051 ms，512 个约为 0.323 / 0.161 ms。它不包含场景提取、GPU 或目标设备帧率；详细结果见 `verification/rendering-performance.json`。关闭阴影/探针时跳过参与网格扫描，编辑标记不参与阴影。

## 示例与验证

导入 `examples/rendering-lab.arkglide` 查看 PBR、软阴影、HDR IBL、Lightmap/AO、自发光和成对视图的组合。播放后点击画面，按 1/2/3 切换低/中/高画质。该示例使用小型程序纹理，目的是验证管线与资源流转，不代表成品游戏的美术质量。局部探针的选择与材质隔离另有单测和 WebGL 测试。

```sh
npm run example:rendering
npm run export:game -- examples/rendering-lab.arkglide 空目录
npm run test:rendering:browser
```
