# 渲染补全：实时探针、时间抗锯齿、场景折射、扩展体积大气

2026-10-21，用户选定前次列表的 1、2、5、6，授权实现后直接提交 main。四项作为同一轮交付，不以计划、开关或局部原型作为完成。动态分辨率/时间超分与动态 GI 不在本轮。

## 顺序和完成条件

1. **实时反射探针**：兼容现有静态 `.env`，增加实时模式、捕获尺寸/周期/层掩码、全局面数/像素/活跃数量预算；分帧捕获六面，完整 mip 链完成后发布，隔离捕获反馈。GPU 原生粗糙度过滤；材质实现捕获更新和盒边界的实际取样混合，提供可观测的捕获与等待统计。
2. **运动向量、TAA 与历史重投影**：使用 Babylon 原生浮点速度缓冲和材质抖动，启用运动历史重投影及邻域裁剪；第一帧、镜头跳切、相机/尺寸/质量变化清空历史。与 SSR/AO/景深、探针、体积、透明共存；不支持时回退 FXAA。
3. **场景折射与分层透明**：提供显式环境/场景透射材质选择；独立 HDR 场景捕获供真实屏幕投影折射，保留 IOR、厚度、吸收、法线与粗糙度。多透明层使用原生双向深度剥离，限制层数；能力不足时报告并回退排序透明。避免捕获自反馈和无限递归，明确有限层和屏幕外边界。
4. **扩展体积大气**：GPU 高度云层的三维密度、风、光路自遮挡；点光/聚光灯的距离和锥角散射，有限预算；多阶散射近似补偿。与原高度雾统一透射合成，保留深度边缘，控制步数和像素开销。

每项贯通共享配置/校验、编辑器、脚本及类型、保存撤销、独立包资源和诊断。默认不改变旧项目效果；资源随修改、停止、重启和销毁释放。

## 计算职责

捕获、GGX 取样、折射、透明剥离、速度/历史与体积积分留在 GPU。CPU 调度受 32 探针/小灯数约束；捕获使用现有 RenderBatch/WASM 大批量视锥筛选，不为小数组增加 WASM 跨界和拷贝。

## 定向检查（按用户要求不跑大验证）

只跑新配置/生命周期必要单测、TypeScript 检查和一个覆盖四项的独立浏览器场景：动态反射与预算、运动/镜头切换、折射背景变化/透明层顺序、云与局部灯开关、High/Low/High、停止资源释放。检查独立沙箱导出使用本地资源。仅发生实质问题时增加对应检查；不跑全量单测、完整编辑器浏览器套件或生产构建。软件 WebGL 结果不充当真实显卡性能证据。
