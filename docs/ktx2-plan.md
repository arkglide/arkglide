# KTX2 / Basis 压缩贴图实施计划

在静态实例批次验收后实施。目标是让游戏使用实际 GPU 压缩贴图，并使编辑器、运行时与独立导出都能离线解码。

- 支持 2D 单层 KTX2 的 ETC1S / UASTC4x4（可选 Zstd）和 RGBA8；按设备选择 ASTC、BC7、ETC 等格式，无支持时回退 RGBA。首版不增加立方体/数组/HDR KTX，也不内置图片编码器。
- 固定 Babylon 9.28 解码器版本；JS、WASM、工作线程和许可证随项目交付。所有解码依赖使用本地 URL，独立包不请求外部 CDN。
- 文件导入先检查容器尺寸、层级、偏移、数据长度和支持格式，再在工作线程用 WASM 完整解码验证。失败、超时、替换竞争或切换项目都不写入过期结果。
- 文件色彩空间贯通材质：颜色图尊重 KTX 的声明；法线、粗糙度、AO 等数据图要求线性编码。验证方向、UV 变换、裁切透明和设备格式回退，避免贴图颠倒或重复 gamma 转换。
- 贯通材质贴图槽、资源替换/引用保护、保存/剪贴板/预制体、静态资源分块和预算报告。HTML UI 图片继续使用浏览器原生图片格式。资源预算区分文件大小、源尺寸/mip 和依赖设备的实际 GPU 格式。
- 验收：使用自行生成的非对称色块/数据贴图，检查真实压缩 GPU 上传、RGBA 回退、颜色与朝向、坏文件拒绝、替换和清理；验证独立包在子路径加载时只有本地请求。最后完成类型检查、相关回归与生产构建，直接推送 main。
