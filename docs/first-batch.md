# 第一批：生命周期、恢复与基础诊断

本版在上一轮编辑器修复版上继续实现 F17、F22 和 F21 的基础诊断。未接入物理、联机、材质编辑器或独立游戏导出。

## 时间与生命周期（F17）

项目设置新增时间倍率、固定步频率和最大追赶步数。默认 1 倍时间、60 Hz 固定步、每帧最多追赶 8 步。

启动顺序：加载场景与模型 → 建立所有脚本实例 → 按父节点优先、挂载列表顺序调用 `onStart`。每帧先调用零次或多次 `onFixedUpdate`，再处理到期计时器，最后调用 `onUpdate`。销毁实体时先清理后代脚本；停止时按实例注册的逆序调用 `onDestroy`，随后释放资源和实体。

```js
return defineScript({
  speed: 3,
  onStart() {
    timers.every(1, () => console.log('游戏时间经过一秒'));
    events.on('score', value => console.log('分数', value));
  },
  onFixedUpdate() {
    this.entity.translate(this.speed * time.fixedDeltaTime, 0, 0);
  },
  onUpdate() {
    // 单次按键边沿适合在逐帧更新中消费。
    if (input.wasKeyPressed(' ')) events.emit('score', 1);
  },
  onDestroy() {
    console.log('销毁前仍可访问实体', this.entity.id);
  }
});
```

| 时间字段 | 含义 |
| --- | --- |
| `deltaTime` / `totalTime` | 缩放后的逐帧时间与累计时间，秒 |
| `unscaledDeltaTime` / `unscaledTotalTime` | 不受倍率影响的游戏运行时间，仍排除暂停 |
| `fixedDeltaTime` / `fixedTotalTime` | 固定步长与已执行固定步的累计时间 |
| `fixedFrameCount` / `frameCount` | 固定步计数与逐帧更新计数 |
| `interpolationAlpha` | 未执行固定步的剩余时间占一步的比例 |
| `timeScale` | 可在脚本内修改，范围 0–100 |

暂停会冻结时间和脚本计时器；恢复第一帧的间隔为零，避免跳跃。倍率为零会冻结缩放时间、固定步和计时器，但 `onUpdate` 仍会收到零 `deltaTime`。单帧时间最多取 0.25 秒，超过最大追赶步数的固定步积压会丢弃；诊断面板显示丢弃量，因此严重卡顿时固定步累计时间可能落后于逐帧时间。

### 脚本拥有的资源

- `timers.after(seconds, callback)`：按缩放后的游戏秒数执行一次，返回取消函数。
- `timers.every(seconds, callback)`：重复执行，返回取消函数；卡顿时每帧最多补一次，不制造回调风暴。
- `events.on/once(name, callback)`：运行内的共享事件，返回取消订阅函数。
- `events.emit(name, payload)`：向当前运行的订阅者发送事件。
- `events.listen(target, type, callback, options)`：登记原生事件监听，暂停时不执行回调，销毁时移除监听。
- 工厂注入的 `setTimeout/setInterval/clearTimeout/clearInterval` 兼容毫秒参数，但使用游戏时间，不是墙上时间。计时器 ID 只属于当前脚本实例。

这些资源在实例工厂失败、实体销毁或停止时统一清理。`onDestroy` 调用一次；清理过程中不接受新的计时器或订阅。同步钩子报错后仅禁用该钩子，其他实例继续执行；计时器或事件订阅报错后取消对应回调。

生命周期钩子按同步函数调度，不等待返回的 Promise。直接调用 `window.setTimeout`、直接向 DOM 注册监听，或自行创建异步请求，会绕过管理接口；脚本须自行取消这些外部任务。使用上述注入接口可以获得停止与销毁清理保证。固定步不等于物理引擎，物理仍是 F11。

## 自动保存与恢复（F22）

编辑内容在停止输入约 1.2 秒后写入独立恢复副本；持续编辑时最长约 10 秒尝试一次。页面失焦、隐藏或退出时也会尝试写入。模型二进制、场景、脚本和设置在同一恢复事务中保存。

自动保存失败时保留当前编辑内容和已有副本；继续编辑或让页面失焦可重试。自动保存不会覆盖手动保存的项目。工具栏显示等待、保存中、已保存或失败状态；点击「恢复」打开列表。启动时若存在副本，会显示恢复入口，由用户选择，不会自动替换当前项目。

恢复列表只读取概要，不读取全部模型二进制。最多保留最近 20 个副本；每个编辑文档保留最新副本，而不是每次按键的历史版本。当前副本在内容成功手动保存后清除；其他副本可以删除。

恢复前先校验格式、节点、层级、设置和资源引用；失败时保留当前项目。缺失模型会标记并显示提示。模型二进制无法从已清空的浏览器存储中凭空恢复。

项目格式升级为 `0.2`，接受缺少版本标记的旧数据及 `0.1`，迁移时补充时间设置。未知新版本、重复模型引用、不合法资源路径和损坏 ZIP 会报错，不能悄悄降级覆盖。模型在手动保存时也会清理已失去引用的项目内二进制。

浏览器关闭或崩溃不能保证最后一次异步写入完成，恢复保证以「恢复副本已保存」为准。若最新更改尚未写入，会尝试触发浏览器离开提示；浏览器可能按自身交互策略不显示提示。请继续使用 `.arkglide` 导出进行跨设备备份。

## 基础诊断（F21）

底部新增「运行诊断」，约每 0.5 秒更新：FPS、本帧 CPU 与峰值、脚本与渲染同步耗时、实体/脚本/网格/材质/贴图计数、加载中模型、计时器/订阅/监听数量、时间倍率、固定步计数和丢弃时间。

停止后保留诊断数据，便于检查计数是否回到基础值。运行器自身包含一个基础相机和环境灯；计数归零不适用于这些基础对象。JS 堆大小仅在浏览器提供时显示，不代表 WASM 内存或 GPU 显存；CPU 耗时也不是 GPU 帧时间。

脚本错误携带文件、钩子、实体和堆栈。运行堆栈包含源码行时，控制台可点击跳转到 Monaco 对应行；编译语法错误若浏览器未提供源码行，则只显示文件和阶段，打开文件首行，不伪造精确位置。控制台最多保留 1000 条消息，避免长期运行日志无限增长。

```bat
npm test
npx playwright install chromium
npm run test:browser
set NODE_OPTIONS=--max-old-space-size=6144
npm run build
npm run analyze:build
```

构建报告列出文件数量、总大小、逐文件 gzip 估算和最大的 12 个文件。这是体积分析工具，不表示已完成代码拆包或全部性能优化。
