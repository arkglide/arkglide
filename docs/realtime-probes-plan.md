# 下一阶段：实时立方体反射探针

已按用户本轮授权完成实时捕获、双缓冲发布、预算、材质过渡、编辑器和独立导出。最终实现及边界见 [渲染补全](rendering-completion.md)。本文件保留原方案；验证范围按用户最新要求缩减为定向检查。

## 场景与配置

在既有局部探针定义中显式区分静态环境与实时捕获，保留旧项目及 `.env` 工作流。实时探针有世界位置、盒范围、优先级、反射强度、分辨率、更新周期和可选捕获层；默认关闭。设置通过同一校验、保存、撤销、脚本类型、编辑属性与独立导出路径。

首版按完整六面为一轮更新，使用前后两份立方体纹理。每帧只提交预算允许的面，六面完成且 mip/粗糙度过滤就绪后才发布新纹理，避免表面混用不同时间的半更新立方体。相机移动、探针移动、内容修改和资源释放都必须有明确的失效/取消规则。

## 捕获与预算

复用 Babylon 原生立方体渲染与现有视图预算模块，新增确定性的探针调度；先在 JS 中明确队列、优先级和公平性，再把有规模收益的批量筛选/评分接到已有 WASM 路径。GPU 捕获与过滤仍在 GPU 上完成。

全局限制每帧捕获面数、像素数、活跃探针数和最长刷新间隔。诊断区分本帧捕获面、完整更新轮次、等待探针、立方体尺寸、估算存储和回退数量。透明、粒子、体积、SSR、平面反射和传送门不递归捕获；初版使用单独的简化捕获规则并明确效果差异。捕获期间须隔离探针自身的反射材质，防止读写同一纹理及递归反馈。

## 反射应用与过渡

保留现有局部盒投影和确定性优先级规则，明确静态/实时重叠时的选择。新旧捕获及探针边界过渡需要额外采样与材质插件；先验证 PBR 粗糙度、清漆、KTX2 法线、光照图和实例材质兼容，再公开混合功能。不能把材质硬切换描述为平滑过渡。

无所需纹理/LOD 能力时使用静态环境回退，并在诊断显示原因。实例批次首版继续沿用探针项目的保守回退，直到支持按反射状态拆分实例组。

## 验收

使用移动色块、移动遮挡物和粗糙度球阵，像素验证六面内容、移动更新、盒投影、完整轮次发布和边界过渡。记录实际渲染面数/像素，确认预算与公平性；覆盖修改、删除、切换相机、质量变化、暂停、停止、重复启动和加载取消。最后验证独立沙箱包只请求本地资源，并完成类型检查及必要的定向配置/生命周期/组合浏览器检查后推送 main；用户明确要求不再跑大验证，因此本轮不运行完整回归和生产构建。目标机帧率与显存预算单独采样。

运动向量/TAA/重投影已在同一轮交付。动态分辨率、时间超分和动态 GI/多次间接光未纳入用户此次选择。
