# 体积大气与后续渲染计划

起点：`cd76c76`。按用户指定顺序先完成体积大气，再推进剩余能力；每项独立实现、示例、验收后直接推送 main。

## 1. 体积大气（已完成）

- GPU 沿主视线积分高度衰减雾与世界空间噪声密度，计算 Beer–Lambert 透射和 Henyey–Greenstein 单次散射。
- 使用场景中首个启用的方向光。独立、稳定的正交光深度图提供屏幕外遮挡，保留既有普通/级联表面阴影，不抢占灯光的阴影生成器。
- 低分辨率积分、深度引导合成，限制积分步数、像素数和光深度图分辨率。GPU 像素计算不搬到 WASM；已有 WASM 批量剔除与几何处理继续复用。
- 编辑器提供开关、雾色/密度/高度/衰减/距离、环境与方向光散射、相位、噪声及质量预算。设置贯通校验、保存、撤销、脚本类型、静态导出与诊断。
- 默认关闭；开启时替代主场景原距离雾，避免重复衰减。没有方向光时仍支持环境高度雾；缺少所需 WebGL2/HDR 能力时回退原距离雾并在诊断中报告。
- 范围是主相机的不透明/裁切深度。透明层使用后方不透明深度；反射和传送门没有独立体积积分。云层、局部灯体积、多次散射和时间重投影后续独立实施。
- 验收：WebGL 像素确认雾的深度/高度层次、遮挡光束与移动遮挡物、零密度等价、低分辨率前景边界、相机/窗口/质量切换、借用深度保留、反复启停与独立包。记录实际采样尺寸和预算，不把软件渲染结果作为目标显卡帧率。

## 2. 大场景性能

先做可明确降低绘制调用的静态实例批次，保留节点拾取/变换和阴影，保守处理材质、透明、骨骼、脚本和 LOD 兼容条件。再接入自包含的 KTX2/Basis 解码与压缩贴图导入、引用、预算、静态分块加载和释放，避免独立游戏依赖外部解码 CDN。

## 3. 反射与图像稳定

接着做有每帧捕获预算的实时立方体探针及过渡，再做运动向量、TAA/重投影、动态分辨率与时间超分；每一项需要单独的像素和资源回归。现有 SSR、平面反射和环境透射继续作为基础。

## 4. 更高阶光照

最后规划动态 GI/多次间接光、真实场景折射与分层透明；保留浏览器端的显存、带宽和移动设备回退预算。真实显卡预算须在目标机使用已交付的场景基准采集。
