# 四阶段画质升级计划

目标：为桌面浏览器的室内 3D 游戏提供可编辑、可保存、可独立导出的光照与后处理管线。按阶段顺序实施和提交，最终回归后推送 main。旧项目默认保持原画面；新增效果显式开启。

## 1. 软阴影、IBL、曝光与色调映射

- 新增共享渲染配置与资源管理器，编辑器、预览和独立包共用；支持异步加载取消、资源替换与销毁。
- 方向光/点光源阴影、网格投射/接收开关、软阴影能力回退、分辨率/灯光数预算。
- 导入预过滤 `.env` 和 Radiance `.hdr` 环境资源，支持 IBL 强度、旋转与天空盒。
- 统一曝光、对比度和色调映射；项目设置加入画面面板。
- 验收：旧项目兼容、非法参数原子拒绝、异步替换无泄漏；真实 Babylon/WebGL 阴影及 IBL 像素验证；保存/恢复/导出包含资源。

## 2. 烘焙光照、AO 与局部反射探针

- 自有 PBR 材质支持外部烘焙 Lightmap（UV 通道和强度）与 AO 贴图。
- 接入可调 SSAO，按 GPU 能力回退，不影响旧项目。
- 项目资源定义带空间范围的局部反射探针，绑定预过滤环境资源；基于物体世界中心选择探针，局部立方体投影，移出范围恢复全局 IBL。
- 不新增离线光照烘焙器；Lightmap 由 Blender 等 DCC 烘焙后导入。
- 验收：UV2/线性色彩空间、AO 参数、探针边界与移动物体切换、预制体/资源依赖、编辑与独立包一致。

## 3. 自发光贴图、Bloom 与统一调色

- 自有 PBR 材质支持自发光贴图与强度；配置 Bloom 阈值、权重和尺寸。
- 场景统一饱和度和色调控制，在 HDR 线性空间完成效果后统一输出转换。
- 传送门纹理保持线性 HDR（设备不支持时回退），避免重复曝光/色调映射；明确粒子与后处理的离屏边界。
- 验收：真实像素对照证明自发光/Bloom/调色有效，主视图与门内亮度一致，关闭恢复且重复启停无管线泄漏。

## 4. 画质档位、GPU 分析、多视图预算与 WASM

- 低/中/高/自定义画质控制阴影、AO、Bloom、抗锯齿和渲染比例，运行时可切换。
- 可用时采集 GPU 时间，始终提供实际绘制数、三角形、离屏视图/像素和 CPU 提交耗时；不把 CPU 时间称作 GPU 时间。
- 传送门按屏幕可见性、投影面积、递归深度排序，并限制每帧视图数与总像素；视图不足时稳定回退。
- C++/WASM 批量执行多视图预算计算，复用连续缓冲；小批次和不可用 WASM 走同语义 JS 路径。GPU 光栅化/材质计算继续交给 Babylon，避免逐对象跨边界调用。
- 验收：JS/WASM 一致性、异常/内存增长/销毁、真实多门场景视图与像素预算；基准包含数据复制与调度成本。整体单测、类型检查、浏览器、独立导出和生产构建通过。

## 共用接入要求

- 资源引用贯通项目校验、存储、撤销/恢复、预制体依赖与静态分块导出，禁止删除仍在使用的贴图。
- 编辑器与运行时使用同一配置规则和实现；脚本接口仅暴露有所有权边界的配置/诊断，不暴露 Babylon 私有对象。
- 引擎保持通用，不写入具体游戏规则。记录实测范围，不用 SwiftShader 的结果宣称目标设备帧率。
